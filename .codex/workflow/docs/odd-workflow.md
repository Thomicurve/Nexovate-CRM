# ODD — V3, proportional execution

Route first with .codex/workflow/docs/request-routing.md. DIRECT and DELEGATED_SMALL do not run
the feature lifecycle below. ODD uses explore, resolve real decisions, implement and
proportionate checks. Existing roles are conditional capabilities, not mandatory stages.
Reference: [Gentle AI ODD](https://github.com/Gentleman-Programming/gentle-ai/blob/5140c5f55baf91763198eb0bfca019c015e3b015/docs/usage.md#organic-driven-development-odd).
Plan/design approval and substantial WU review are local deliberate controls.
RDD is not enabled/emulated/required; never invoke its commands merely because this is ODD.

## Classification and preparation

Investigation/proposal-only stays read-only: no feature artifacts/branches/mirror.
Locate/edit/check are one bounded outcome; number of tool calls/files does not define
substantial work. Multiple meaningful behavior/architecture outcomes, material UI,
complex dependencies or recoverable progress do. Inspect an unfamiliar path proportionately
before assigning risk. Security/auth/credentials/data loss/concurrency/migrations/
installation/public contracts or unresolved high-consequence risk need independent proof.
A small critical fix may use inline criteria and the independent checks/review below without
an artificial spec if no durable tracking is useful; it cannot use unchecked DIRECT execution.

Only named material gaps justify specialists: Discovery functional ambiguity; Product complex
behavior/ACs; Story Writer optional useful/requested Stories, exclusive author; Explorer
unknown dependencies; Architect significant technical decisions; Designer material UI/UX.
Primary/Implementer can read known scoped files themselves. Favicon replacement, copy and
existing cosmetic conventions do not activate Designer/frontend-design/Pencil. Actual
material design uses editable Pencil approval and current node/state verification.
Greenfield lacking a chosen stack needs options/user choice before architecture/scaffolding.
Batch independent currently answerable decisions, keep IDs/options/rationale/custom path,
wait for submitted answers; no interpretation of omissions/canceled questions as consent.

For substantial work persist specs/<feature>/spec.md (definition) and task.md (Stories/Tasks/minimal state) after exploration and before application writes.
Use .codex/workflow/docs/templates/odd-feature.md and .codex/workflow/docs/templates/odd-task.md for those planning artifacts.
Record intent/scope/ACs/approach, verifiable Tasks/real dependencies/allowed paths/checks,
TDD when relevant, risk, coherent WU/commit boundaries and user approval references.
Present the document locator/Task count and concise current plan/design/delivery.
Obtain explicit approval of exact PLAN/design; readiness, memory, silence or tool access is
not user approval. Material deltas reopen affected plan/approval/evidence only; preserve
valid completed and unrelated work. No new scope from findings alone.

## Tracked execution

Follow .codex/workflow/docs/task-execution.md: one ready authorized Task in the current checkout,
at most one writer, same dedicated requirement branch, no task worktrees/branches/launchers.
Supply actual root/ref/base/baseline, current assigned inputs, criteria/paths/dependencies
and exact authority/checks. Implementer stops after its selected task and cannot continue.
Codex selects ASK_EACH_TASK or CONTINUOUS with current-plan approval. ASK_EACH_TASK waits
for named continuation; CONTINUOUS advances serially within the approved revision and stops
at blockers/material changes/user interruption. Mode choice alone does not approve a plan.
Feature states: PREPARING / WAITING_FOR_USER / READY / IMPLEMENTING / CHECKING / BLOCKED / DONE.
Task states: TODO / IN_PROGRESS / BLOCKED / DONE. Orchestrator alone owns state/user choices.
Substantial DONE needs accepted criteria/checks/review and verified WU commits, not readiness.

## Checking and review

Normalize before checking; start focused. Passive content needs structural/link/readback proof,
ordinary behavior functional proof. TDD ON/OFF follows explicit choice or unambiguous applicable
policy, with source/runner; ON requires observed RED before behavior, then GREEN/REFACTOR.
Passive asset/copy/Git-only work is N/A unless an explicit applicable policy requires TDD.
Only an unresolved choice affecting the action needs a question; existing tests do not enable TDD.
Re-run affected checks after changed bytes/paths/modes. Missing proof is INSUFFICIENT_EVIDENCE.

Reviewer inspects every substantial WU after writer stops; small high-risk work also needs
independent review. High or unresolved high-consequence risk gets a fresh verification-only
Implementer invocation to inspect the diff/run exact checks without edits or writer conclusions.
APPROVED permits authorized commit; CHANGES_REQUESTED returns supported defects to writer or
real decisions to user; INSUFFICIENT_EVIDENCE obtains proof, not speculative code changes.
Closure reuses accepted unchanged WU receipts; review/check only unreviewed integration and
feature criteria. No duplicate full pass merely because the final task finished.
A changed candidate invalidates affected proof; persistent blockers are reported instead of
repeated unchanged dispatches. Static contract tests are not autonomous runtime acceptance.

## Delivery, memory and migration

Consult .codex/workflow/docs/delivery-and-tracking.md only for branch/commit/PR or authorized Linear work.
About 400 authored changed lines is advisory, never artificial splitting/compression.
Forecast for substantial work, choose cohesive delivery once when risk/size warrants and
retain it while scope remains valid. Commit each accepted substantial WU with tests/docs.
DIRECT uses actual current branch/project restrictions, scoped operations and matching
authority; FEATURE delegates mutating Git to Implementer Delivery. Push/PR/merge/release
need corresponding authority; PR request includes necessary scoped push. No force/reset/
stash/overwrite/broad staging. Inspect uncertain results before retry, verify real identities.

Consult .codex/workflow/docs/engram-memory.md for selected durable facts and feature continuity.
New V3 features use a compact current record, meaningful checkpoints and verified readback,
not a full document mirror after each handoff. Local artifacts remain authoritative; unavailable
memory permits continuation only with sufficient current authority/proof. No credentials/raw logs.
Existing features retain their old locator/mirror/continuation policy until explicit migration.
Read/reconcile prior evidence, preserve IDs/criteria/decisions/completed work, confirm migration
and save continuity on the same stable topic. Never silently replace a legacy mirror.
Install a coherent runtime bundle; do not mix old agents with V3 routing/permissions.
Publication of templates does not install/activate them or prove runtime acceptance.
